# 「开始自动秘域」支持路线/禁区/丹药设置自动探索

## 需求

在原有「开始自动秘域」（发 `秘域快捷开始`，游戏自动随机探索）基础上，新增多行带设置的命令，实现自动探索秘域地图：按设置的路线选地区、追禁区、自动携带丹药并出发。
固定路线通过独立命令持久保存（按机器人分别保存），启动探索时用“指定路线：是/否”决定是否启用已保存路线。
固定路线配置命令与开始探索命令分开发送；保存后可重复用于后续探索。

命令格式（指定路线 与 禁区选择 至少一项；携带丹药可选）：

```
设置秘域路线
路线：青石道 试剑崖 弑师坪
路线：玄火洞 寒潭谷 落星原

开始自动秘域
指定路线：是
禁区选择：是
携带丹药：随机
```

- **固定路线**：用 `设置秘域路线` 单独配置并持久保存，每条路线填写 3 个地区名，可重复填写多行 `路线：`，也可在一行用分号分隔；用 `查看秘域路线设置` 查看，`清空秘域路线设置` 删除。进入探索时 `指定路线：是` 启用保存的路线，`否` 跳过路线。
- **路线匹配**：地图上任意一条已保存路线的 3 个地区全部出现，就按该路线顺序点选；多条同时匹配时选配置靠前的一条。
- **禁区选择**：是/否；未设置时默认否（不追禁区）。
  - 是：必须同时设置携带丹药才启动，否则提示“必须携带丹药才可以进入”并拒绝启动。地图刷出「禁」级地区（如 禁·往生台）→ 选它 + 其余地区中难度最高的 2 个；没刷出禁区 → 点「刷新路线」继续刷（游戏上限 6 次/日）；6 次后仍没有 → 选当前 6 个中难度最高的 3 个。
  - 否：不追禁区。指定路线启用但未匹配时刷新路线，最多 6 次；仍未匹配则按当前地图 高>中>低 选择难度最高的 3 个（排除禁级地区）。未启用指定路线时直接按难度兜底，不刷新路线。
- **难度排序**：禁 > 高 > 中 > 低。
- **携带丹药**：指定 3 种（天命血凝丹/归藏灵丹/九阳真丹/太元真丹/养元丹 五选三不重复）/ `随机`（随机 3 种）/ 不填（不点丹药，选完地区直接出发；禁区选择为“是”时不可留空）。
- 不带任何设置单发「开始自动秘域」→ 完全保持原有快捷流程（`秘域快捷开始`）。
- 带设置时，出关后触发的命令由 `秘域快捷开始` 改为 `探索秘域`，进入地图自动选择流程。

## 技术基础

- bot-core 原生支持真实按钮点击：`bot.clickKeyboardButton(groupId, botAppid, buttonId, callbackData, msgSeq)`（NapCat `click_inline_keyboard_button` 扩展），项目内验证码自动点击、灵石确认已在生产使用。
- 按钮获取两路：handler 参数注入 `Buttons`（NapCat），失败时 `Utils.parseButtonsFromMessage`（Utils.java:377）从消息 `json[...]` inline_keyboard 段兜底解析，并用 get_msg 反查 msgSeq。注入+兜底写法参考 `自动点击按钮` handler（TestService.java）。
- 多按钮串行点击间隔复用常量 `BUTTON_CLICK_INTERVAL_MS=2000`，任务提交到 `customPool`，参考 `clickButton`。
- 按钮标签格式：地区=`低·青石道`（危险等级·地区名称）、丹药=`天命血凝丹`，另有 `刷新路线(...)`、`出发`、`清除所选地区`、`清除所选丹药`。进入时不点击卡片上的「出发」，而是在选丹药后 @小小 发送 `确认秘域出发`。

## 消息识别方案（三重过滤）

1. **状态机（主判定）**：`WAIT_MAP` 只认地图卡；点完 3 个地区后 `WAIT_PILLS` 只认备药卡；`CLICKING_ROUTE`/`CLICKING_PILLS` 过渡态忽略游戏回发的新卡片，防重复触发。
2. **按钮结构（必要条件）**：地图卡 = ≥3 个标签匹配 `^[低中高禁]·` 的地区按钮；备药卡 = 按钮中出现白名单丹药名。两类按钮集合不相交。
3. **文本标记（辅助确认）**：地图卡 contains「秘域探险」「本次现世地区」「请点选」；备药卡 contains「请选择备药」「候选丹药」。标记定义为常量，若与真实 markdown 报文有出入只需改常量（日志有"未识别按钮消息"可诊断）。
4. **归属校验**：卡片 markdown 提及的 `at_tinyid == botId` 才处理，避免同群其他玩家的卡片干扰。

## 实现

### 新增 `data/MiYuExploreContext.java`

探索上下文（内存态，与 botConfig 待执行命令机制一致，重启丢失重发命令即可）：

- `routes`（当前任务启用的候选路线；固定配置保存在 `config/bot-{botId}.json` 的 `miYuRoutes` 字段）、`forbiddenZone`（禁区选择，未填时默认 false，不选禁级地区）、`pills`、`randomPills`
- 状态机：`WAIT_START`（设置已保存等出关，不参与超时清理）→ `WAIT_MAP` → `CLICKING_ROUTE` → `WAIT_PILLS` → `CLICKING_PILLS` → 移除
- `refreshCount`（已刷新次数）、`lastActiveTime`（超时清理依据）

### TestService.java

- 成员：`miyuExploreMap`（botId → 上下文）；常量：`MIYU_MAX_MAP_REFRESH=6`、`MIYU_CONTEXT_TIMEOUT_MS=30分钟`、丹药白名单、地区按钮正则。
- 命令入口：`设置秘域路线` 整体替换并持久保存该 bot 的路线，`查看秘域路线设置` 查看，`清空秘域路线设置` 删除；每条由 `路线：` 加3个地区名组成。`开始自动秘域` 解析 `指定路线：是/否`、`禁区选择：`、`携带丹药：`；指定路线为是但没有已保存路线时拒绝启动；禁区选择为“是”但未设置丹药时也拒绝启动。
- 触发点两处（startAutoTask 空闲分支、出关完成补发分支）统一走 `sendMiYuExploreStart`：有上下文 → `探索秘域` 并置 `WAIT_MAP`；无 → 原 `秘域快捷开始`。
- 新 handler `秘域地图选择`（senderIds=3889001741）：
  - 地图卡：启用指定路线时按持久配置顺序检查，任意一条路线的3个地区全部匹配即点选该路线；多条都匹配时选配置靠前的一条。都未匹配 → 最多点 6 次 `刷新路线`（计数+1，保持 WAIT_MAP 等新地图卡），仍未匹配则按当前地图难度兜底。未启用指定路线时跳过固定路线匹配。选完后进入 WAIT_PILLS。
  - 备药卡：指定 → 点对应丹药按钮；随机 → 随机 3 个；不设置 → 跳过。丹药选择完成后 @小小 发送 `确认秘域出发`，不点击卡片上的 `出发` 按钮；命令发送后移除上下文，由现有秘域结算流程（`道友已入【幽都】…约N分钟` → myTimeMap → 定时 `秘域结算`）接管。
  - 异常兜底：按钮解析失败 @主人 提醒手动处理；收到"已经参加过本次秘"终态消息放弃本次探索；`停止执行` 清理上下文；30 分钟无活动自动清理（WAIT_START 除外——闭关数小时后才出关属正常等待）。

### 防护与细节

- 每次刷新路线游戏收 900 万灵石；若弹"请确认是否…灵石"确认卡片，现有 `自动点击按钮` handler 会自动点「确认」。
- 串行点击在 customPool 执行，不阻塞 handler 线程。
- `秘境帮助` 菜单已补充多行格式说明。

## 使用示例

```
开始自动秘域
指定路线：是
禁区选择：是
携带丹药：天命血凝丹 归藏灵丹 九阳真丹
```

只按危险等级选：

```
开始自动秘域
禁区选择：否
携带丹药：随机
```

不启用指定路线时按难度兜底，禁区为否时不刷新路线：

```
开始自动秘域
指定路线：否
禁区选择：否
```

## 上线观察点

- 首次实跑关注日志："秘域地图卡命中"/"秘域备药卡命中" 表示识别成功；出现"秘域等待地图中收到未识别按钮消息" 说明文本标记与真实报文有出入，仅需调整 TestService 中标记字符串常量。
- `at_tinyid` 归属校验沿用验证码点击的既有先例，若协议端不回填 tinyid 会退化为全文匹配 botId。
