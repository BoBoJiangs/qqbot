# 运行状态持久化排查

本清单记录最初静态核查时的情况，检查了主机器人任务、小北、炼丹与采购、捡漏与上架、灵石赠送、定时任务、提醒和验证码模块。

**后续实施进度：用户指定的四类已补充持久化，包括悬赏令/秘境自动结算、秘域计时与本轮探索、群内悬赏/秘境/秘域提醒、自动灵田与群灵田提醒。** 具体保存和恢复规则见 [游戏任务重启恢复](游戏任务重启恢复.md)。下表其余项目仍是排查建议，未在本次扩展实施，也未对线上数据库或机器人执行操作。

`LocalDataFiles` 已把原来以 JSON、TXT、SER 路径访问的运行数据写入 SQLite，因此“类里有 Map”或“路径以 .txt 结尾”均不能说明没有持久化。判断依据是业务状态能否写入、加载，以及重启后是否有续跑入口。

**已经存入 SQLite，不应重复当作遗漏。**

- 机器人普通配置、秘域固定路线、各群丹方匹配开关：`BotConfigPersist/BotConfigManager`。
- 炼丹设置、药材价格、部分配方和背包文本：经 `LocalDataFiles` 保存；`DanCalculator.java:125` 还能从药材价格重建采购名单。恢复路径受启用炼丹及配置中的 `alchemyQQ` 等条件影响，因此“资料存在”仍不代表活动任务自动继续。
- 重复采购药材名称、价格、数量限制：`AutoBuyHerbs.java:389-465` 已有加载/保存。
- 灵石赠送收款配置、累计、已占用接收码及回执去重：`LingShiGiftStore.java:108-141` 已保存。
- 传功提醒：`GroupManager.java:1314` 注册时已有立即保存。
- 群购买提醒开关、专属提醒条件、炼金/上架排除配置、打怪记录、令牌奖励时间：已有存档路径，部分注册/更新方法会立即保存。
- 自定义定时任务的新增和周期检查、机器人连接快照和未送达异常通知、更新通知、Web 登录凭据：已有持久化入口。
- 坊市价格、限价：通过现有 JPA 数据层保存；当前数据库配置已切换为 SQLite。

**适合保持内存或重新获取的内容。**

- Bot、Group、WebSocket 连接、线程池、锁、Future、调度器实例：保存它们代表的业务任务即可，不能序列化这些对象恢复。
- 当前页原始消息、按钮对象、短期验证码图片/点击序号、旧消息对象：重连后重新获取，避免使用失效消息或按钮。
- 从持久化资料计算出的配方索引、市场价缓存、物品分类表、成语库：启动时重建即可。
- 几秒级请求去重、网络在途标记、GC 调度标记、刚收到消息的昵称归属缓存：通常不必逐个入库；真正跨重启需要保留的是已发送业务指令与结果的关联。
- `XiaoBeiService.AUTO_BUY_PRODUCT` 当前只发现声明、未发现有效读写；注释掉的 `XiaoYueService` 也不应按活跃业务新增持久化。

建议实施顺序：先修复计时/提醒与保存时机，再补任务状态、采购/炼丹/上架与赠送的执行记录，最后补循环任务、小北、坊市续跑及提醒节流。恢复时以游戏端实际状态校准；采购、赠送、炼金、上架等指令不能仅因本地没有收到回执就直接重复执行。
