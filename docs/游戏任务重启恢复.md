# 游戏任务重启恢复

本次只补充以下四类数据；自动炼丹、采购、小北、赠送、循环执行等其他运行流程仍按原逻辑处理。

| 数据 | 保存时机 | 重启后行为 |
|---|---|---|
| 悬赏令、秘境自动结算时间 | 收到计时、校准时间、确认结束时立即保存 | 按账号恢复原绝对到期时间，沿用自动结算开关与模式；已到期的任务在连接恢复后的轮询中继续处理 |
| 秘域到期时间、本轮探索流程 | 入境/剩余时间回复、路线刷新计数及流程阶段变化时立即保存 | 恢复本轮路线、禁区、备药参数和快捷流程；重新获取游戏当前卡片，再继续处理，不保存或重放旧按钮 |
| 群内悬赏、秘境、秘域结算提醒 | 创建提醒时立即保存；确认发送成功后删除并保存 | 保留原目标 QQ、群、负责发送的机器人和到期时间；该机器人离线或发送失败时保留，后续轮询重试，不再因超时 30 分钟丢弃 |
| 自动灵田时间、群内灵田提醒 | 收到剩余时间、收取结果和创建提醒时立即保存 | 自动灵田恢复原时间，收到新的游戏计时才替换；群提醒在负责机器人上线后补发 |

## 使用和存储

无需新增配置。数据通过项目现有的 `LocalDataFiles` 写入 SQLite，默认数据库为 `config/qqbot.db`，也可由 `QQBOT_DATABASE` 指定。下列路径是数据库里的逻辑文档标识，不会额外生成同名 JSON/SER 文件：

- `cache/game-task-state/{机器人QQ}.json`：三类自动结算时间和本轮秘域探索。
- `cache/task_data.json`：已有群数据文档，新增“悬赏秘境秘域提醒”，灵田提醒改为即时保存。
- `cache/field_remind_data.ser`：沿用自动灵田文档，改为时间变化即时保存，并保留正常关闭时的兜底保存。

升级继续兼容旧灵田存档及不含新增提醒字段的群数据。正常运行时不依赖关机钩子保存这些关键变化，进程被结束或服务器重启后也能读取最近一次已提交的数据。

首次换用本版本前，旧程序只放在内存且从未入库的计时和提醒无法自动追回；需要重新收到游戏计时或重新设置提醒。已有旧灵田存档仍会加载，随后以游戏返回的新时间校准。

## 恢复规则

- 停机期间不会暂停或重置倒计时。到期时间已过，也会保留为待处理状态。
- 自动结算发送请求后保留时间，等待游戏返回结束结果或新的剩余时间。原有自动功能开关、验证码异常和手工处理规则继续生效。
- 秘域等待出关的流程会恢复“开始自动秘域”意图；已开始选地图、备药或提交出发的流程，每分钟至多重新查询一次当前状态。进入秘域并取得计时后，同一次存档更新会清除准备阶段，避免重启后再次准备出发。
- “停止执行”会同时清除本次悬赏令、秘境、秘域自动结算及探索存档，防止人工停止的任务重启后继续。自动灵田和群提醒仍由各自原有开关控制。
- 群结算提醒开关关闭时继续按原有规则取消对应提醒；机器人离线与发送失败不视为主动取消。发送回执成功后立即移除并保存，尽量避免重复提醒；发送成功与本地存档之间恰好进程中断时仍可能再次提醒。
- 不持久化 Bot、连接、线程或按钮对象。点选时连接断开会保留探索参数，重新查询当前卡片；卡片无法解析时仍保留原有手动处理提示。单个账号存档恢复失败会记录日志并重试，不阻塞其他账号恢复。

## 验证

新增自动化测试覆盖绝对时间恢复、状态即时保存与清除、账号隔离、秘域点选中断恢复、快捷流程与等待出关恢复、人工停止、离线补提醒、发送失败重试、灵田计时更新及旧格式兼容。测试使用隔离的 SQLite 数据库与模拟机器人，不向真实 QQ 发送消息。
