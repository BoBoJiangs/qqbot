# 机器人重启连接监测

程序每 30 秒查询各账号的实际在线状态，并通过现有 `LocalDataFiles` 存储到 SQLite。默认数据库为 `config/qqbot.db`，配置 `QQBOT_DATABASE` 时使用指定数据库。逻辑文档键为 `config/bot-connection-state.json`，不会额外生成同名 JSON 文件。

JavaBot 重启、服务器重启后，应用就绪满 5 分钟后的下一轮检查开始比对上轮确认在线的账号，检查时仍未恢复的账号按各自配置的 `masterQQ` 合并成一条告警，优先私聊，所有在线候选账号均非好友时改发提醒群并 @该 `masterQQ`。昵称、QQ、当前状态、最后确认在线时间、快照时间、启动时间和检查时间都包含在消息内。默认检查间隔为 30 秒，状态查询和发送还需少量时间。

## 在线及好友判断

- 使用 [OneBot 11 `get_status`](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_status-获取运行状态) 的 `online`、`good` 判断状态。WebSocket 已断开、QQ 离线、请求失败或超时分别记录，无法确认的账号不会当作恢复成功或发送方。
- 优先选择配置了相同 `masterQQ` 的在线账号，发送前再次确认在线并调用 `get_friend_list` 查询实际好友列表。不是好友或查询失败时跳过该账号，不使用缓存推断好友关系，不自动添加好友。
- 发送失败切换其他在线好友账号，只有成功回执且返回有效消息 ID 才视为已发送。配置 `masterQQ: 819463350` 即向此 QQ 通知，代码未写死收件人。
- 确认所有在线候选账号都不是该 `masterQQ` 的好友时，使用顶层配置 `xxGroupId` 指定的群兜底，例如 `xxGroupId: 690933736`。选择实际已加入该群的在线机器人，群消息中通过真正的 @消息段提醒 `masterQQ`。群发送失败切换其他账号，成功后停止，不重复发送。
- 好友关系查询失败、超时，或已经确认是好友但私聊失败时，继续保留待通知记录重试。无法确认好友关系不等于不是好友，不据此触发群兜底。没有配置有效 `xxGroupId`、没有机器人在该群或群发送均失败时，也保留记录重试。
- 所有账号恢复只记录日志，不发成功消息。没有可用发送方时保留待通知记录，每分钟重试；重试前重新检查，已经恢复的账号不再列入异常。
- 原有掉线事件通知也使用同一发送流程，通常在下次 30 秒检查内发送；同一账号恢复前不重复告警。重启检查名单中的掉线事件合并到重启告警，避免启动期间重复提醒。

## 持久化与重启

连接建立和掉线事件同步更新记录；正常停止及程序主动重启时，在销毁连接之前冻结最近确认的状态，关机阶段不请求网络。突然断电、强制终止只能使用最后成功保存的快照。

上轮在线名单与本轮状态单独存储，未送达告警的名单在连续重启后仍然保留。首次启用没有历史快照，只建立本轮记录，从下一次重启开始进行比对。状态记录损坏时保留原始内容并停用本轮监测，日志记录原因。

服务器重启后需要由现有部署方式自动启动 JavaBot，并保留数据库。JavaBot 自身启动失败或一直没有可用 QQ 账号时，无法即时通过该程序发出 QQ 通知；待程序和发送方恢复后才能继续检查、发送。

## 可选配置

默认直接启用，无需修改现有 `masterQQ`。可在应用配置中添加以下顶层配置（不要放入 `bot` 列表）：

```yaml
xxGroupId: 690933736

bot-connection-monitor:
  enabled: true
  startup-delay-ms: 300000
  snapshot-interval-ms: 30000
  retry-interval-ms: 60000
```

`enabled: false` 会关闭重启监测及接入此服务的掉线通知。所有时间均以毫秒配置，通知中的时间按北京时间显示。
