# KNN 错题与人工纠错

管理后台入口：`/admin/knn-review`，使用现有管理员登录与密码策略。

## 使用流程

1. KNN 无可用答案，或提交后游戏明确判错/再次返回同一验证码时，机器人提交对应快照编号。
   服务端把原图和该次检测框、主模型标签、KNN 预测、题目及失败原因保存到独立队列。
2. 打开“KNN 人工纠错”，逐个核对真实图标与标签。可删除背景框，拖动新增/移动框，修改坐标。
   预填值只是预测；点击“确认保存并下一张”才算人工确认。
3. 分类错误选择“分类错误”；背景误检、漏框、顺序问题选择“检测问题”，后者只归档。
4. 核对完成后点击“发布已确认样本到索引”。原始 618 张、2486 个图标的基准索引会保留，
   发布时重建为“基准 + 当前已确认分类纠错样本”。同图去重，多次发布不会重复追加同一批样本。
5. 已确认样本可以重新打开修改、撤销确认或忽略；再次发布后会移除旧标签/撤销的样本。

发布在后台提取特征，沿用当前分类模型和 KNN 特征方案，不训练或修改主模型。
发布前备份旧索引，写入失败回滚；发布成功后立即用于 KNN，无需重启识别服务。
错题可通过“背景抑制预览”查看不同参数下的实际检测与 KNN 结果。失败记录包含当次背景处理参数，
原图继续保留，分类纠错的发布仍使用原图特征。详见 `KNN_BACKGROUND.md`。
新增标签也必须在当前分类模型的合法标签列表内，确认样本增加后可扩大 KNN 类别覆盖。

只有人工确认的分类样本进入索引，系统不会把失败时的预测答案自动当作正确答案。
KNN 成功、按钮接口异常、服务/会员异常、过期、无回执、人工接管均不会自动进入错题队列。
“无可用答案”并不一定是分类错误，需要人工判断问题类型。
直接在 QQ 客户端人工点击无法区分来源，接管前应切到手动模式。

## 存储

默认识别服务工作目录下：

```text
knn_review/
  pending/              KNN 短期快照，默认保留一小时，尚不算错题
  errors/images/        KNN 错题原图，按原图内容哈希去重
  errors/records/       失败来源、预测与人工纠错 JSON
  baseline/             首次发布时保存的完整原始基准索引
  index_backups/        每次发布前的索引备份
  publication.json      最近发布的样本修订版本
```

线上挂载目录为 `/home/captcha-api/knn_review/`。可通过 `KNN_REVIEW_DIR` 修改位置，
通过 `KNN_REVIEW_PENDING_TTL_SECONDS` 修改临时快照有效期。
目录、当前 `knn/reference_index.npz`/`reference_meta.json` 应随服务数据一起备份；
后续发布代码不要用初始索引覆盖已发布的纠错索引。

需要同时更新识别 API 和 Java 机器人，新版本才会上报 KNN 的明确失败。
旧版混合错题没有可靠的 KNN 来源标记，不会被自动推断或迁移进新队列。

## 效果边界

正确、具有代表性的人工样本有助于改善 KNN 分类，但错误标注也会影响后续结果。
新发布样本后应观察“验证统计”中的 KNN 成功率；KNN 只接收首次失败后的样本。
该流程无法直接修复检测模型的背景误检、漏检和排序错误，需要另行处理检测数据与模型。
